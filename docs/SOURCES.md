# Document sources: the adapter model

Confluence and Backstage are not special. Every document source is an **adapter**: a small class that lists the
documents a scope should contain. The ingest engine does everything else the same way for every adapter, so JAMA,
a wiki export on disk, a git repo, SharePoint or an internal API are all the same amount of work: one file.

```
adapter.documents(scope)  ──►  engine: diff versions → batch into that scope's LightRAG → reconcile deletions → commit state
```

## What an adapter is

> Authoring guide with the full framework (`Plugin`, `Source`, `LiveSource`, `McpUpstream`): [PLUGINS.md](PLUGINS.md).

A subclass of `Source` (`ingest/ingest/sources/base.py`) with a `name` and one required method:

```python
from ingest.sources import Source, Document, ScopeContext

class WikiExportSource(Source):
    name = "wiki-export"

    def __init__(self, options=None):
        super().__init__(options)
        self.root = self.option("root", "/data/wiki")      # non-secret option from `sources:` in scopes.yaml
        self.token = self.env("WIKI_TOKEN")                 # secret from config/stack.env

    def configured(self) -> bool:                           # optional: skip cleanly when not set up
        return bool(self.root)

    def documents(self, ctx: ScopeContext, filter: dict | None = None):
        for page in load_pages(self.root, ctx.config.get("sections", [])):   # ctx.config = the scope's docs: entry
            yield Document(key=page.id, version=page.updated_at, text=page.markdown, title=page.title)
```

| Field | Meaning |
|---|---|
| `key` | stable within (adapter, scope); becomes part of the LightRAG source id |
| `version` | any string that changes when `text` changes: a revision number, an updated-at, a content hash |
| `text` | what LightRAG indexes; prepend a small header (source, path, URL) so answers can cite it |
| `title` | optional, prepended as a heading |

Optional methods: `covers(key, filter)` tells the engine which previously seen keys a filtered (webhook) run
enumerates, so it can delete the ones that disappeared; without a filter everything is covered.

## Where adapters come from

Two discovery paths, checked at startup; a scope only ever references the adapter's `name`:

1. **`plugins/`** in the repo, mounted read-only at `/plugins` (compose bind mount; Kubernetes ConfigMap generated by
   `make gen`). Every `*.py` there is imported; its `PLUGIN` (or bare `Source` subclass) is registered. The shipped
   ones (`confluence`, `backstage`, `git`, `files`, `jama`) live here too: the engine has no built-ins, so an
   org-specific source is exactly as first-class as Confluence.
2. **Installed packages** declaring an entry point in group `context_stack.sources`, for adapters you want to
   version and test as a proper package:
   ```toml
   [project.entry-points."context_stack.sources"]
   jama = "acme_sources.jama:JamaSource"
   ```
   (install it into the ingest image with a one-line `pip install` in `ingest/Dockerfile`.)

Explicit override: `sources: { name: { type: "pkg.mod:Class" } }` in scopes.yaml points a name at a class.

## Configuration surface

Three places, each with one job, so a new source never touches the ingest code or the shared config module:

| Where | What | Example |
|---|---|---|
| `config/stack.env` | secrets and endpoints, read by the adapter with `self.env()` | `JAMA_URL=…`, `JAMA_TOKEN=…` |
| `config/scopes.yaml` → `sources:` (optional) | non-secret adapter options, `self.option()` | `jama: { page_size: 100 }` |
| `config/scopes.yaml` → scope → `docs:` | what of that source belongs to this scope, `ctx.config` | `jama: { projects: [42] }` |
| `config/scopes.yaml` → scope → `code: { repos: [...] }` | the scope's repositories, shared by code search, the code graph and the `git` docs plugin (`ctx.repos`) | |

The `docs:` map is the access-control decision: listing a source under a scope says "everything this adapter yields
for this config may be read by everyone in the scope's groups". The adapter must honour that by skipping anything
with a finer ACL (Confluence page restrictions are the shipped example).

## Developing an adapter

```sh
make source-check SCOPE=payments SOURCE=jama            # runs documents() and prints keys, versions, previews
make source-check SCOPE=payments SOURCE=jama ARGS="--filter '{\"project\": 42}' --limit 5 --full"
```

No LightRAG involved; it only needs the adapter's credentials. When the listing looks right, `make sync` (or
`POST /sync/jama`) ingests it; `GET /sources` on the ingest shows every discovered adapter and whether it is
configured. Webhooks: `POST /webhook/<name>` with a JSON body that your `documents()` understands as `filter`.

## Freshness: when documents are pulled

Eagerly, never at query time. `query_docs` reads the scope's LightRAG index only; a source system is contacted
solely by the ingest, on three triggers:

| Trigger | Latency to a fresh answer | Notes |
|---|---|---|
| Webhook from the source (`POST /webhook/<adapter>` with a filter) | minutes, dominated by LightRAG's extraction | Confluence Cloud, GitHub/GitLab push, JAMA events can all call it; `INGEST_WEBHOOK_SECRET` guards it |
| Schedule (`INGEST_SCHEDULE_CRON`, nightly by default) | up to one interval | tighten it for sources without webhooks |
| Manual (`make sync`, `POST /sync/<adapter>` or `/sync/all`) | immediate | after config changes or re-scoping |

Every run is incremental: adapters yield `(key, version)` per document, the engine re-ingests only changed keys,
deletes keys that disappeared, and commits `versions.json` after LightRAG accepted the batch. There is no in-place
update in LightRAG, so a changed document is deleted and inserted again; that and the extraction are what make a
change take minutes rather than seconds to show up in answers.

Pulling at query time is deliberately not done: it would put a source round-trip plus minutes of LLM extraction in
front of every answer. If a source must be answered live, that is a different tool (a direct API tool on the
gateway), not an ingest adapter.

Known cost: listing is only as cheap as the adapter makes it. The Confluence adapter fetches page bodies together
with versions, so a large space is downloaded on every run even when nothing changed. Adapters for big sources
should list versions first and fetch text only for changed keys (a two-phase `documents()`); an engine-level hook
for that is on the list.

## Fallbacks: live sources and MCP upstreams

The index can lag or miss. A plugin's **live part** is the query-time twin of its ingest part: it searches or reads
the system of record directly, through the gateway, under the same scopes. It is declared on the plugin
(`Plugin(live=..., mcp=...)`) and on by default; the optional top-level `live:` map of `config/scopes.yaml` only
overrides per plugin. What each caller may reach comes from the same per-scope `docs:` entries the ingest uses, so
there is one access decision, not two:

```yaml
live: {}                                   # nothing needed: plugins declare their fallbacks
# live:
#   confluence: { enabled: false }         # switch a plugin's fallback off
#   confluence: { fallback: false }        # keep live_search/live_fetch, but query_docs will not consult it
#   confluence: { via: rest }              # talk to the REST API instead of the declared MCP upstream
#   confluence: { url: http://mcp.elsewhere:9000/mcp, auth_env: ATLASSIAN_MCP_TOKEN }   # an upstream you run
```

The Confluence plugin declares **[sooperset/mcp-atlassian](https://github.com/sooperset/mcp-atlassian)** (MIT) as
its upstream, so `make gen` runs it as the `mcp-confluence` service/pod: streamable-HTTP, stateless, `--read-only`,
only `confluence_search` and `confluence_get_page` enabled, no published port, the service account from `stack.env`
(`CONFLUENCE_URL`/`USER`/`TOKEN`, or `CONFLUENCE_PERSONAL_TOKEN` for Server/Data Center). It runs with
`ALLOW_GLOBAL_CRED_FALLBACK=true` because the gateway, its only client, sends no per-user token; the per-user scope
decision is the gateway's. Keep the REST credentials on the gateway too: mcp-atlassian returns no restriction
metadata, so the plugin cross-checks page-level restrictions through REST.

The miss is decided per scope from LightRAG's own signal: v1.5.7 marks its canned no-context reply with
`llm_generated: false`, and an errored scope counts as a miss too. Only the scopes that missed are searched, with the
question reduced to its distinctive terms (systems of record search by keywords, not sentences).

How it is used:

- **Automatically.** `query_docs` asks the scope's LightRAG first. When a scope's index has no answer (LightRAG's
  canned no-context reply, or an error), the gateway searches every live source with `fallback: true` for exactly
  those scopes and returns the hits under `fallback` with refs; the agent then calls `live_fetch` for the one it wants.
  Pass `fallback: false` to skip.
- **Explicitly.** `live_search(source, query)` and `live_fetch(source, ref)` are tools in their own right, for "the
  page changed five minutes ago" situations.

How the scope is enforced for an MCP upstream: the gateway never forwards the agent's arguments. It builds the
upstream query itself (for Confluence: CQL with `space in (<the caller's spaces>)`, plus mcp-atlassian's own
`spaces_filter`), and checks every returned item's space before handing it back; `live_fetch` refuses anything whose space is outside the caller's scopes.
Page-level restrictions are honoured when the transport exposes them (REST does). MCP upstreams rarely return
restriction metadata, so with `via: mcp` the Confluence plugin cross-checks every hit and fetch through the REST API
when `CONFLUENCE_*` credentials are present; without them a fetch reports `restriction_checked: false` and search
results cannot be filtered on restrictions. For sources where that matters, keep REST credentials configured, or use
an upstream that authenticates as the *user* so the source enforces its own ACL.

Writing one: add a `LiveSource` subclass to the plugin file and pass it as `Plugin(live=...)`, optionally with the
upstream image as `mcp=McpUpstream(...)`; see [PLUGINS.md](PLUGINS.md).

## Rules that keep the model safe

- Never yield source code: code belongs to Sourcebot and CodeGraphContext.
- Never yield content whose ACL is narrower than the scope; skip it.
- Keys must be stable across runs; changing the key scheme re-ingests everything.
- Keep `text` as clean text or markdown; strip HTML, keep headings and a header with the source URL.
- Read secrets from the environment only; options and scope config are committed to git.
