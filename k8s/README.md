# Kubernetes deployment (k3s, OrbStack, or any cluster)

The same stack as `docker/compose.yaml`, with the same service names, so nothing in the gateway or ingest changes.

```
k8s/kustomization.yaml   root: namespace context-stack, base + generated, image overrides
k8s/base/                hand-written: postgres, redis, ollama, hindsight, sourcebot, ingest, gateway
k8s/generated/           GENERATED by `scripts/gen-scopes.py k8s` (gitignored):
                           scope-<name>.yaml   lightrag / falkordb / codegraph / indexer CronJob per scope
                           stack-env.env       Secret `stack-env` = config/stack.env + engine-specific derived names
                           scopes.yaml, config.json, init.sql, index-repo.sh -> ConfigMaps
                           plugins/ -> ConfigMap `plugins` mounted at /plugins (ingest, gateway)
                           mcp-<plugin>.yaml   upstream MCP server a plugin declares (McpUpstream)
```

## Deploy

```sh
cp config/stack.env.example config/stack.env && edit    # secrets + inference backend
docker compose build                         # gateway, ingest, codegraph images
python3 scripts/gen-scopes.py k8s
kubectl apply -k k8s
kubectl -n context-stack get pods -w
```

Images: OrbStack's Kubernetes shares the Docker image store, so `docker compose build` is enough. On a plain
k3s host: `docker save agent-context-stack-gateway:latest | sudo k3s ctr images import -` (same for `-ingest`
and `-codegraph-public`), or push to a registry and change `images:` in `k8s/kustomization.yaml`.

Models: in-cluster Ollama is `deploy/ollama` (PVC `ollama-models`; `kubectl -n context-stack exec deploy/ollama --
ollama pull bge-m3`). For models outside the cluster set `LLM_BASE_URL`/`EMBED_BASE_URL`/`HINDSIGHT_EMBED_BASE_URL`
in `config/stack.env` (OrbStack pods reach the host as `host.docker.internal`), regenerate, and
`kubectl -n context-stack scale deploy/ollama --replicas=0`.

## Operate

```sh
kubectl -n context-stack create job --from=cronjob/indexer-public indexer-public-now   # code graph, per scope
kubectl -n context-stack port-forward svc/ingest 8080:8080 &  && make sync              # docs -> LightRAG
kubectl -n context-stack port-forward svc/gateway 8090:8090 & && make smoke             # ACL checks
kubectl -n context-stack port-forward svc/sourcebot 3000:3000                           # create the API key once
```

Changing `config/scopes.yaml`: regenerate and `kubectl apply -k k8s` again; a new scope adds its pods, a removed scope's
objects must be deleted by hand (`kubectl -n context-stack delete all,pvc -l scope=<name>`).

## Exposure

Every Service is ClusterIP. The gateway must only be reachable through the SSO reverse proxy / Ingress that sets
`X-Forwarded-User` and `X-Forwarded-Groups` (docs/ACCESS-CONTROL.md); add that Ingress in your own overlay. Never
expose the engine Services (hindsight, sourcebot, lightrag-*, codegraph-*) outside the cluster.

## Sizing

Per scope: LightRAG ~1 GB, FalkorDB ~100 MB, CodeGraphContext ~300 MB. Shared: Hindsight ~1.5 GB, Sourcebot ~1 GB,
Postgres, Redis. Ollama needs the model in RAM/VRAM (`gpt-oss:20b` ~16 GB). PVC sizes in the manifests are
starting points; the default StorageClass (`local-path` on k3s) is used.
